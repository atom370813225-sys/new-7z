# 分卷压缩、任务栏图标与启动优化

2026-11-16。本次修改针对原生 WinUI 应用，HTML 原型保持既有范围。

## 交付行为

- 主窗口「新建压缩」及 Explorer「压缩」配置窗口共用 `VolumeSizeField`。默认不分卷；7z/ZIP/TAR 支持预设及自定义大小，最小 1 MiB，支持小数（如 `1.5 GiB`）。Zstandard/LZ4 的分卷选项禁用。
- 输出 `name.7z.001`、`.002` 等原始字节分卷，ZIP/TAR 采用同一命名规则；不是 ZIP 的 `.z01` 独立磁盘格式。所有分卷放在同一目录，从 `.001` 打开、预览、测试和解压；支持密码及 7z 文件名加密。Explorer 识别 `.001`，拖入主窗口也可打开。
- 原生可定位输出流直接写入各卷，支持归档头回写，不先生成完整大文件再切割。临时分卷带任务 GUID；取消或失败清理本次临时文件。提交遇到同名文件会回滚本次已提交卷并保留已有文件。解压预检保护所有源分卷，避免替换源包。整包属性显示全部分卷总大小。
- 分卷 ZIP 创建时明确使用 UTF-8 文件名；把卷依次拼接后，可由 .NET ZipArchive 独立读取中文路径及原始文件内容。
- 启动前不再同步扫描及递归清理临时目录；清理移至后台。主页先显示，再后台检查最近文件及自定义图标，离线共享路径不会阻塞首屏。保留移除失效记录入口。复用启动设置读取，发布启用 ReadyToRun。
- Logo 源文件透明；问题来自打包任务栏资源缺少 `targetsize` 的 `altform-unplated` / `altform-lightunplated` 变体。补齐 15 种尺寸、浅深两组资源；安装版 Shell 身份包生成 PRI，Store 使用项目资源索引。原因依据 [Microsoft 图标说明](https://learn.microsoft.com/en-us/windows/apps/design/iconography/app-icon-construction)。现有安装需要安装新构建后才会获得资源修复。

## 验证证据

- 完整引擎回归 335 项通过；`--volumes-only` 专项 45 项通过（包含在完整回归中）。分卷包含 Unicode 路径、空目录、密码、大小上限、随机内容往返、预览、完整性、同名输出、提交竞态、取消清理、缺中间卷、源分卷写保护、独立 ZIP 读取和单卷边界。
- `--verify-ui`：共享分卷控件实际原生渲染及预设/自定义/非法输入/格式切换通过；设置、任务、归档列表、900 DIP 布局、文本/图片预览及关闭取消通过。开发版报告 `artifacts/verify-volume-ui.json`，裁剪版报告 `artifacts/verify-volume-ui-composed.json`。共享字段采用标准控件组合，避免自定义 WinUI 继承类型在裁剪后发生转换错误。
- `scripts/test-icons.ps1 -IdentityDirectory artifacts/identity-icon-check`：三份 Windows 二进制有 ICO，七种 ICO 尺寸，30 份 PNG 大小及透明像素，PRI 含两组 unplated 资源。
- 独立 `7zSdk/bin/x64/7zr.exe t`：带中文密码的四卷 7z，识别为 Split + 7zAES，`Everything is Ok`。
- `scripts/measure-startup.ps1`：五次进程启动，窗口句柄出现为 476–609 ms，首帧 Rendering 事件为 616–796 ms，报告 `artifacts/startup-after.json`。优化前首次观测创建窗口为 3269 ms，随后两次约 505–509 ms，报告 `artifacts/startup-before.json`。缓存条件不同，不据此计算冷启动提升百分比；未清空系统缓存或重启测量。Rendering 事件也不等于最终像素呈现时刻。
- 电脑界面检查工具返回窗口归属不匹配错误，未取得本轮当前运行截图；以上 UI 证据来自应用自身诊断，不宣称已完成真实任务栏视觉验收。

## 已知边界

分卷包不提供原地修改；需解压后重新创建。缺最后一卷且格式本身不记录完整总长时，不能仅凭连续编号推断缺卷，依赖归档结构/完整性检测。ZIP 使用现有 7-Zip 引擎的 ASCII 密码限制，7z 可用中文密码。
